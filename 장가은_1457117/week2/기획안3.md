# 🦆 AI 아바타 화상회의 모드  
### “카메라를 켜지 않아도, 내 대신 아바타가 회의에 들어가 말해주는 기술”

---

## 📌 주제 한 줄 설명
> **카메라를 켜지 않아도, 개인화 아바타(캐릭터/일러스트)가 내 목소리에 맞춰 립싱크·표정 반응을 하며 화상회의에 참여하는 서비스**

---

## 💡 이 서비스가 뭐냐면요
화상회의에서 **내 얼굴 클론(딥페이크) 없이**,  
내가 고른 **개인화 아바타(캐릭터/일러스트/3D)** 가 화면에 등장합니다.

내가 말하면 아바타가

- 입을 움직이고(립싱크)
- 말투에 따라 표정이 바뀌고
- 눈을 깜빡이거나 고개를 끄덕이며

👉 **“살아있는 사람처럼” 반응**합니다.

그래서 사용자는

- 운전 중 / 이동 중 / 카메라 부담 상황에서도  
👉 **마이크만 켜고 회의에 참여**할 수 있습니다.

---

## 🎯 왜 이게 필요하냐면
- 외근이 많은 영업직 / 이동이 잦은 직무
- 카메라 켜기 부담(복장, 환경, 프라이버시)
- 노트북을 켤 장소/자세를 확보하기 어려운 상황

👉 **“회의 참여는 해야 하는데, 카메라는 부담될 때”** 필요한 기능

---

## ✅ 핵심 컨셉
### 내 얼굴 클론 ❌ → “개인화 아바타 + 립싱크” ⭕

- 사용자는 **아바타 스타일 선택/커스터마이징**(색/헤어/의상/배경)
- 회의 입장 시 **카메라 대신 아바타 영상 스트림 송출**
- **마이크 입력**을 기반으로
  - 입모양(열림/닫힘 또는 5~8개 viseme)
  - 표정(밝음/차분/놀람 등)
  - 말할 때 미세 동작(고개 까딱/눈 깜빡임)
- **“AI 아바타 모드” 토글**로  
  일반 카메라 ↔ 아바타 전환 지원

---

## 🧩 기능 요구사항(요약)
### 1) 아바타 개인화
- 2D 일러스트 / SVG / Canvas 또는 3D 모델(선택)
- 커스터마이징 요소: 피부톤, 헤어, 안경/수염, 배경 등
- **사진 업로드로 얼굴 분석(클론) X**
  - 대신 “닮은꼴 커스터마이징” 중심

**선택 이유**
- 구현 안정성
- 윤리/발표 리스크 낮음
- 체감 만족도 대비 비용 효율적

---

## 🏗️ 기술 구현 설계

### 1) 전체 구현 구조

#### A. 클라이언트(브라우저)
1. **마이크 입력 수집**
   - `getUserMedia({ audio: true })`
2. **음성 분석(Web Audio API)**
   - `AudioContext` + `AnalyserNode`
   - 매 프레임(30~60fps)
     - 음량(RMS)
     - 피치(기본 주파수, autocorrelation 등)
3. **아바타 렌더링**
   - 2D: Canvas / SVG
   - 3D(선택): Three.js + VRM(버튜버 포맷)
   - 분석값으로 “입/눈/고개” 애니메이션 적용
4. **아바타 → 비디오 스트림 변환**
   - `canvas.captureStream(30)`로 비디오 트랙 생성
5. **WebRTC 송출**
   - 캔버스 트랙을 WebRTC에 붙여 전송
6. **카메라 ↔ 아바타 전환**
   - `RTCRtpSender.replaceTrack()`로 **재협상 없이** 트랙 교체

#### B. 서버(시그널링)
- WebRTC 연결용 **시그널링 서버**: WebSocket / Socket.IO
- ICE 서버
  - STUN 기본
  - 외부망/모바일 고려 시 TURN 중요

#### C. 회의 룸(확장)
- 1:1~소규모: P2P 가능
- 3~10명 이상 안정 목표: **SFU 권장**
  - mediasoup / Janus / LiveKit 등

## 👄 “음성만으로 립싱크 + 기분표현” (MVP)

### (1) RMS 기반 입 벌림(가장 단순 + 효과 큼)
- 말할 때: 입 열림(2~5단계)
- 조용할 때: 입 닫힘

**장점**: 서버 AI 없이 프론트에서 실시간 가능  
**한계**: 실제 발음 단위 viseme 수준의 정교함은 부족

### (2) 피치 기반 표정(기분) 규칙
- 피치↑ + 음량↑ → 밝음/강조(미소)
- 피치↓ + 음량↓ → 차분/무표정
- 피치 급변 → 놀람/강조(눈썹↑)

---

## 🔧 아바타(2D) 구현 상세

### 목표
- 브라우저에서 아바타 렌더링
- 카메라 대신 WebRTC 비디오 트랙으로 송출

### 방식
- **파츠 조합형(추천)**  
  얼굴/눈/입(5단계)/눈썹/헤어/악세서리/배경을 PNG/SVG로 분리  
  → 커스터마이징 용이
- **단일 일러스트 + 입만 교체**  
  얼굴 고정, 입 스프라이트만 교체  
  → 구현 간단

### Canvas 렌더링 루프
- `requestAnimationFrame()`에서 매 프레임 그리기
  - 배경 → 얼굴/헤어 → 눈(깜빡임) → 입(음성 기반) → 표정 요소

---

## 🎛️ 입모양(립싱크) 구현 팁(자연스러움 포인트)

### RMS 기반 매핑(예시)
- RMS < T0 → 닫힘
- T0~T1 → 살짝 열림
- T1~T2 → 중간
- T2~T3 → 크게
- T3 이상 → 강조(아주 크게)

### 자연스러움 3요소(중요)
- **스무딩(EMA/이동평균)**: 입 떨림(지터) 제거
- **게이트(노이즈 컷)**: 작은 RMS는 0 처리
- **릴리즈 타임**: 말 끝에 150~250ms로 천천히 닫히게

---

## 🙂 표정(기분) 구현(규칙 기반)

### 입력 특징
- RMS(에너지)
- 피치(높낮이)
- 변화량(ΔRMS, Δ피치)

### 표정 규칙 예(MVP)
- 밝음: RMS↑ & 피치↑ → 미소/볼 홍조
- 차분: RMS↓ & 피치↓ → 중립
- 놀람: Δ피치 큼 → 눈 커짐/눈썹↑

### 2D에서 표현 요소
- 눈썹 각도/위치
- 눈 크기(scale)
- 입꼬리(스프라이트/곡선 변화)
- 볼 홍조(alpha on/off)
- 고개 끄덕임(5~10px 미세 흔들림)

## 🧱 “닮은 정도” 로드맵(3단계)

### Level 1) 닮은꼴 커스터마이징(추천)
- 사용자가 직접 슬라이더/옵션으로 조절
- 구현 부담 낮고 발표 리스크 거의 없음

### Level 2) 사진 1장 → 아바타 파라미터 자동 세팅(클론 아님)
- 얼굴 특징을 추출해 아바타 파라미터에 매핑(캐릭터화)
- 구현 옵션: MediaPipe Face Mesh(랜드마크 기반)

### Level 3) 실제 얼굴 클론(딥페이크급)
- 가능하지만 실시간성/비용/윤리/악용 리스크 큼  
→ 데모/서비스 관점에서 비추천

## ✅ 추천 MVP 스코프(“보기 좋은 데모” 최소 구성)
- 2D 파츠 조합 아바타(헤어/안경/배경 정도)
- RMS 기반 입모양 5단계
- 피치+RMS 기반 표정 3종(밝음/차분/놀람)
- 눈깜빡임 + 고개 미세 움직임
- Canvas `captureStream()` → WebRTC 송출
- 카메라 ↔ 아바타 토글(`replaceTrack()`)
